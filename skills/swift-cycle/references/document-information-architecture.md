# 文档与目录组织

目录、命名、查找或正文重复已经影响维护时读取。以职责和读者任务组织，不以文件数、行数、上下文长度或模板数量拆分。

## 入口与导航

README 面向用户；DESIGN 先解释整体办法与模块职责，再说明详细文件回答什么、怎样关联、何时阅读。小项目可在 DESIGN 承载必要设计和全部导航。只有查找困难时才增加 [docs 首页](../templates/docs/README.md)。

索引写短说明与实际链接，按需要注明用途、读者或状态，不固定四列表格；不复制事实正文。tutorial、how-to、reference、explanation 可帮助选择写法，不是另一套必建目录。

## 路径与命名

- 新项目多词用下划线，品牌与大小写遵守项目约定。
- 根级 README.md、AGENTS.md、DESIGN.md、TODO.md、DEVLOG.md 以及 Skill 的 SKILL.md 保留生态入口名。
- 新普通 docs 文件和多词目录用小写 snake_case，扩展名 .md；目录索引 README.md 是例外。
- 蓝图默认 docs/blueprint.md，需求默认 docs/requirements.md；默认禁止根级 Blueprint、docs/BLUEPRINT.md。
- 编号计划采用 docs/milestones/milestone_1_plan.md、milestone_2_plan.md，编号稳定；milestones 可只含当前一份计划，不额外建索引。
- 代码、测试、锁文件、工具入口遵守语言与工具生态；技能标识 swift-cycle 保持连字符。
- 图及长期说明用稳定用途名原位维护，不堆日期副本、new/old/final2，不套 source-版本-提交号/。
- 已有稳定路径不因整理自动迁移；旧命名偏差需批准的文档整理包，统一修复引用，不复制第二正文。

## 代码和说明的职责

小脚本可用函数区分入口、规则和外部接入。需要打包、导入或独立维护时再用 src/ 等布局；前后端、服务、共享模块只有真实独立职责才拆目录。按语言命名、格式、类型及错误约定实现，注释解释理由和边界。

共用逻辑确有共同含义且降低维护成本才抽取，允许尚无稳定共性的少量重复。不要为未来设想预建框架、对称空目录或完整设计系统。

单篇说明通常留 docs 根；同类内容需独立导航或附件组才建职责目录，如 contracts、operations、evaluation、adr。正式事实保持唯一正文，概要和导读引用它。当前源码、安装、运行数据、恢复点分开；开发材料不全量装入 Skill。

## 有界整理

整理已获授权时，在当前包内核对目标结构、保留项及入链，做可追溯移动和链接修正，再检查唯一正文、相关验证与 git diff --check。不需要逐文件请批。变更权威、删除 tracked 资产、消费者不明或越界时才请求决定。

每包聚焦受影响内容，消除明确重复并轻巡关联入口；反复堆积影响维护或用户明确要求时才扩大整体整理。无用过程不搬进 history、archive 或 ZIP。

## 临时材料与回收

临时文件放已有忽略 tmp/ 或系统临时位置，不另建 AI 产物树。缓存、一次性脚本、中间输出只成为回收候选；build/artifacts 名字不决定去留。用途、使用者、许可及生命周期一致才合并。

回收先核对精确绝对路径、使用者、恢复价值、符号链接/ReparsePoint 边界及当次授权。源码、补丁、构建输入、锁文件、必要测试、安装内容、用户数据和恢复点默认保留；固定合同引用的材料按合同保留路径与身份。

Windows 用回收站，其他环境用核对后的可恢复方式；机制不明、仍被使用或路径越界则保留，不永久删除或清空回收站。Git 历史不能恢复忽略记录、用户数据或运行恢复点。详见 [生命周期](lifecycle-and-closeout.md)。
