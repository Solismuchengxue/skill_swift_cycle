# 需求变化与持续收敛

接收新需求、安排阶段/工作包、维护记录或冻结审查快照时读取。各文档负责什么见[文档职责](document-profiles.md#文档职责与按需选择)，本文件规定何时同步及如何判断完成。

## 需求接收与前瞻调整

先明确问题、预期行为和验收，再判断对当前包、依赖、设计及完成条件的影响，提出加入、替换或后移。确认需求不等于立即排期；PRD 保留仍有效需求，BLUEPRINT 构想不自动成为承诺。

| 变化 | 实际处理 |
| --- | --- |
| 原需求澄清 | 范围未变，补准确表述及验收 |
| 原要求未满足 | 按缺陷修正，保留原标准；旧完成判断有误则纠正 |
| 新增或改变能力 | 更新确认需求，决定取舍后调整设计、阶段和工作包 |
| 已完成阶段后新增需求 | 安排后续包；有独立阶段结果才新增里程碑，不无故重开原阶段 |

已有决定直接同步；目标/范围实质变化或优先级冲突集中请用户决定，并继续不依赖答案的已授权工作。编号稳定，不另写需求变更流水；收敛旧计划时保留完成范围、必要结论、固定引用及授权证据。

## 阶段与实施分工

- ROADMAP：跨包阶段、依赖和退出判断确需独立维护时建立，跨会话/机器本身不触发。当前阶段写清，远期留方向与已知依赖，日期/资源只写真实承诺；阶段不等于版本、Release 或项目结束。
- 编号计划：详细顺序、影响或独立审阅确有需要时使用 docs/milestones/M{N}_PLAN.md。一阶段一份现行计划，不建日期副本、每包计划或空未来计划。
- TODO：摘要当前位置、差距、当前包与后续，链接既有路线图/编号计划。未划分里程碑如实说明，不虚构编号或为填表新建路线图。
- 工作包：按依赖与影响拆出可检查小结果，包含实现、验证和说明同步；独立实验也可成包。普通修正在包内完成，缺必要条件才阻塞，不因 W 编号创建目录、分支、提交、审查或新 Agent。

无新增实质授权或目标变化不逐包请批。已采用 Superpowers 时按[衔接条件](superpowers-bridge.md)执行。

## 每包同步与轻巡

开始工作先核对既有 TODO 的目标、阶段和事实；实质进展、发现问题、阻塞出现或解除、完成或取消时，在下一次实质行动或对外汇报前同步。

| 触发变化 | 同步位置 | 完成判断 |
| --- | --- | --- |
| 需求、行为或验收变化 | PRD、相关用户说明 | 确认行为与验收一致，旧有效需求保留 |
| 目标、用户、核心场景、能力边界或关键约束变化 | BLUEPRINT | 长期意图反映已确认变化，不混入维护流水 |
| 模块、接口、数据或运行/交付职责变化 | DESIGN 与相应详细正文 | 方案、实现位置及入口引用一致 |
| 阶段、依赖或退出条件变化 | 既有 ROADMAP、编号计划；TODO 摘要定位 | 一阶段一份现行计划，完成条件独立核对 |
| 工作进展、问题、阻塞或完成状态变化 | TODO | 已达成/剩余差距准确；问题有影响与解决判断，延期有去向，不静默移除 |
| 形成有效维护经验 | DEVLOG；影响安排时回写 TODO 或相应正文 | 紧凑条目保留结论、理由及必要边界，不复制完成流水 |

结果和必要验证满足后才勾选 TODO；总体完成条件满足后才切换里程碑并补后续事项，未知如实说明。不按勾选比例推算整体进度，待办不构成外部动作授权。

每包消除明确重复和过时引用，轻巡受影响入口；不扩成全仓审计、哈希、manifest 或重写全部文档。规则/测试已完成而 README 仍是旧行为，当前包尚未完整交付。

TODO/DEVLOG 的栏目与条目格式见[记录约定](document-profiles.md#todo-与-devlog)。无用完成项确认不承担当前决策或固定引用后才移除；不整批转入 DEVLOG，也不转存 history/ZIP。长期事实写回对应正文，本地留经验或链接。

## 完成判断

- 工作包：核对预期结果、必要检查与受影响说明。
- 里程碑：另核对总体退出条件、代表性交互/协作和必要人工确认；任务全勾选不等于阶段完成。
- 验证：区分文件/解析/构建/加载、隔离模拟、真实使用和长期观察；未检查层明确未验证。
- 运行或数据变更：另核对当次环境、恢复条件和窗口。工具缺失不自动安装；已有检查通过且无新变化不扩大重测。

在授权内继续下一项，范围变化先调整。无文档影响不制造改动或报告；源码实现、用户审阅、发布及真实采用分别判断。

## 候选与有效经验

候选留 PRD 待确认或相关 DESIGN/SAD，不预设独立评估文档。实际试用收集直接证据，比较与结论留对应正文，形成重要长期决定才写 ADR/正式设计；试用不等于采用。

经验同题原位提炼，保留重要拒绝理由、适用条件、必要未知和固定证据；重要结论改变时留清原边界。稳定失败防线可写原因、修正断言和未来检查位置，不强制每条四字段或每包新增 DEVLOG。

## 审查、交付与退役

优先复用已有结论与证据链接；实际接收方确需快照或摘要时才整理，不预设模板或每阶段报告。

审查快照标日期/里程碑，交付后冻结；修正进入新快照或现行正文，不把旧快照改成现行真源。摘要只报告项目证据，不产生外部验收、激活、发布、运行授权或组织状态。

退役材料前核对当前正文、入链、消费者、替代项、历史决定及恢复价值。固定合同引用保留路径与身份；删除和运行切换另核权限。消费者不明、不可安全恢复或越界则保留；回收方式见[临时材料与回收](document-profiles.md#临时材料与回收)，Git 历史不替代本地数据和恢复点。
