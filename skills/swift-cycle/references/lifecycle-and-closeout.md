# 需求变化与持续收敛

接收新需求、组织阶段/工作包、维护记录或冻结审查快照时读取。

## 需求接收与前瞻调整

BLUEPRINT 承载项目目标、愿景、用户、场景、核心能力和产品边界，不承诺所有构想。PRD 保留已确认且仍有效的行为、约束和验收；未定想法进待确认事项，已实现需求不删除。DESIGN/SAD 依据确认需求，ROADMAP 与编号计划选择当前需求而非直接拆蓝图构想。

收到新消息先明确问题、预期行为和验收，核对当前包、依赖、设计及完成判断的影响，提出加入、替换或后移。确认需求不等于立即排期；已有决定直接同步，目标、范围实质变化或优先级冲突时集中请用户决定，并继续不依赖答案的已授权工作。

| 变化 | 实际处理 |
| --- | --- |
| 原需求澄清 | 范围未变，补准确表述及验收 |
| 原要求未满足 | 按缺陷修正，保留原标准；旧完成判断有误则纠正 |
| 新增或改变能力 | 更新确认需求，决定取舍后调整受影响设计、阶段与包 |
| 已完成阶段后新增需求 | 安排后续包；独立阶段结果才新增里程碑，不将原阶段无故改为未完成 |

编号稳定，按实际职责原位同步，不另写需求变更流水。旧计划过程可收敛，完成时的范围、必要结论、固定引用及授权证据保留。

## 阶段与实施分工

路线图仅在跨包阶段、依赖与退出判断需要独立维护时建立；跨会话或机器本身不是触发。当前阶段写清，远期保留方向与已知依赖，日期/资源只写真实承诺。阶段不是版本、Release 或整个项目结束。

详细顺序、影响或独立审阅确需计划时，使用 docs/milestones/M{N}_PLAN.md，一阶段一份现行计划；不新增日期副本、每包计划或空未来计划。包可用 W1 等标识、短列表或表格，不因此建目录、分支、提交、审查或新 Agent。TODO 摘要当前进度、里程碑位置与差距，链接当前包，列待办/问题、阻塞和后续阶段；已有路线图/编号计划保持唯一正文，不复制完整计划。未划分里程碑如实说明，不虚构编号或为填表新建路线图。

一个包得到可检查小结果，包含必要实现、验证、说明同步；按依赖和影响拆分，独立实验也可成包。普通修正在本包完成，缺少必要条件才阻塞。无新增实质授权或目标变化，不逐包请批。已采用 Superpowers 的本地衔接见 [衔接条件](superpowers-bridge.md)。

## 每包同步与轻巡

- 行为与验收变化同步 PRD 及用户说明；项目目标、用户、核心场景、能力边界或关键约束实质变化时同步 BLUEPRINT。
- 模块、接口、数据、运行/交付责任变化同步 DESIGN 与详细正文；只改相关内容和入口引用。
- 开始工作先核对既有 TODO 的目标、当前阶段及事实；实质进展、发现问题、阻塞出现或解除、完成或取消时，在下一次实质行动或对外汇报前同步，不等用户提醒。发现问题立即归入当前待办，写影响和解决判断；延期事项写明去向与影响，不静默移除。
- 结果与必要验证满足后勾选 TODO，更新已达成/剩余差距；完成条件独立核对后才切换当前里程碑并补下一阶段事项，后续未知如实说明。阶段事实同步既有路线图/编号计划，TODO 仅摘要定位；不以任务勾选比例推算整体进度，也不把列入待办当成外部操作授权。
- 每包消除明确重复和过时引用，轻巡关联入口；不是每包全仓审计、哈希、manifest 或重写全部文档。
- DEVLOG 只在有用经验形成时写“日期｜主题”的紧凑条目，结论与理由为核心，依据/影响按需补；记录多到影响查找时按真实里程碑分组，无里程碑不强设。单条不用子标题或固定多字段；同题持续提炼，保留重要拒绝理由、适用条件、未知和固定证据，重要结论变化留清原边界。经验影响当前安排时回写 TODO 或对应正文。
- 无用 TODO 完成项可在确认不承担当前决策/固定引用后移除；不整批或汇总搬入 DEVLOG，不转存 history/ZIP。长期事实同步对应正文，本地只保留经验或链接。

例如规则与测试完成而 README 仍是旧行为，当前包尚未完整交付，应先修正说明再继续，不能以“项目尚未结束”推迟。

## 完成判断

包完成核对预期结果、必要检查及受影响说明。里程碑另核对阶段总体退出条件、代表性交互/协作以及必要人工确认；任务全部勾选不等于阶段完成。

验证报告区分文件/解析/构建/加载、隔离模拟、真实使用与长期观察；未检查层明确未验证，工具缺失不自动安装，已通过且无新变化不重复扩大测试。运行或数据变更另核对当次环境、恢复条件和窗口。

在授权里继续下一项，范围变化先调整。无文档影响不制造改动或专门报告。源码实现、用户审阅、发布及真实采用是不同结论。

## 候选与有效经验

想法在 PRD 待确认或相关 DESIGN/SAD 中标候选，不预设单独评估文档。实际试用收集直接证据，方案比较和结论留在对应职责正文，形成重要长期决定才写 ADR/正式设计；试用不等于采用，必要验证和未知仍须保留。稳定失败防线可提炼失败模式、原因、修正断言与未来检查位置，不强制每条 DEVLOG 四字段或每包新增条目。

## 审查、交付与退役

审查或收尾优先复用已有结论与证据链接；实际接收方确需有界快照或交付摘要时才整理，不预设固定模板或每阶段报告。审查快照标明日期/里程碑，交付后冻结；后续修正进入新快照或正文，被替代的快照不改写为现行真源。摘要只报告项目证据，不产生外部验收、激活、发布、运行授权或组织状态。

退休材料前核对当前权威、入链、消费者、替代项、历史决定及恢复价值。固定合同引用保留路径与身份；删除和运行切换另核对权限。用已核对可恢复方式，消费者不明、不可安全恢复或越界则保留。不要以 Git 历史代替本地数据和恢复点。
