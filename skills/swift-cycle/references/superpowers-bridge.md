# Superpowers 本地衔接条件

仅在项目已选择 Superpowers 实施且需要衔接编号计划时读取。Swift Cycle 默认不依赖它，不安装或修改插件。

## 唯一计划与任务提取

编号里程碑计划保持唯一正式正文。writing-plans 的默认日期路径可由用户路径约定覆盖；不得另存一份 docs/superpowers/plans 日期计划。固定中文二级栏目保留，目标、约束、设计、规格和审阅关注点放在相应栏目，不重复两套标题正文。

衔接前读取实际安装版本的指令和解析器。若 task-brief 按“Task N”标题提取，则在“实施顺序”内使用三级技术标题，例如“### Task 1: W1 比较规则”；编号与 W 包对应。W 表格、中文包标题本身不等于可解析任务。技术标记保持原文，内容用项目语言。

每个任务包含必要文件、接口/依赖、具体行动、验收和文档同步。执行者同时读取唯一计划及确认需求/设计，不能假设 brief 自带全局范围与授权。任务正文引用全局约束，而不是重复复制。

解析器可能只在下一个 Task 标题停止，最后一项会连带之后的总体验证、风险和当前状态。核对真实输出及边界；如这些栏目作为全局上下文被保留，明说其作用，不将其误当成最后任务独占职责。若工具语义与项目规则冲突，保留正式计划，报告不兼容，不为适配静默改规则。

## 执行记录与授权

brief、测试输出、progress 仅是忽略的临时执行状态，不是第二份正式实施计划或新的事实权威。结果变化后同步编号计划及 TODO 当前位置，避免两套当前真源。不要删除仍有作用的 workspace 以重新开始。

核对 task-start/task-done 所需工作目录、HEAD、BASE 和测试命令。只在检查成功且任务实际完成时记录；辅助脚本成功不代表阶段退出、独立审查或用户接受。调用 Bash 辅助器时显式使用已核对的 Bash interpreter，不依赖文件执行位或 Windows WSL shim。

原插件的完整流程可能要求工作树、审阅、提交和最终整理；本地提取及记账通过不证明整套流程兼容。不得由衔接推导安装、提交、推送、多 Agent 或外部副作用权限；缺失授权的步骤明确不执行。

## 验证声明

只有实际运行支持才声明本地最小衔接通过，并说明版本、任务边界和验证范围。静态阅读不是执行证据；模拟 fixture 不是业务项目采用。完整执行、跨项目采用、目标宿主及长期恢复未测则保持未验证。一次性结果留在维护仓库的兼容说明，不让安装包依赖包外文件、机器路径或测试身份。
