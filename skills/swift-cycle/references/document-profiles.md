# 文档职责与固定模板

创建、重整文档或判断权威时读取。先复用现有等价来源，只补缺失且实际需要的职责；不把模板清单变成生成清单。

## 最小职责选择

minimal 覆盖持续项目的用户、愿景、需求、必要设计与执行入口；获准创建/正式初始化必含根级 TODO.md、DEVLOG.md。standard 只增加需独立维护的详细架构、阶段安排、评估或决策。runtime_integration 只增加当前真实涉及的运行、合同、安全、存储和集成层。单篇专业说明不意味着铺开更高档位。

不要求逐职责裁剪表、固定字段、状态 Schema 或新报告。唯一事实来源、实际缺口与触发条件清楚即可。

| 目标文件或等价来源 | 职责与建立条件 | 模板 |
| --- | --- | --- |
| README.md | 持续项目的用户入口：用途、接入、首次使用、求助和限制 | [README](../templates/README.md) |
| docs/blueprint.md | 新建持续项目的受跟踪愿景、用户、场景和产品边界；旧项目复用完整等价来源 | [蓝图](../templates/BLUEPRINT.md) |
| docs/requirements.md | 持续迭代的已确认有效需求、行为边界与验收；一次性任务复用现有明确要求 | [需求](../templates/docs/requirements.md) |
| DESIGN.md | 有设计时维护整体方案、实现位置及详细文档导读 | [设计](../templates/DESIGN.md) |
| docs/architecture.md | 简洁 DESIGN 已无法承载详细结构、协作与关键机制时 | [架构](../templates/docs/architecture.md) |
| AGENTS.md | 采用项目执行规则时；只写局部差异和读取条件 | [执行规则](../templates/AGENTS.md) |
| docs/roadmap.md | 跨工作包的阶段、依赖与退出判断需要独立维护时；跨会话/机器本身不是理由 | [路线图](../templates/docs/roadmap.md) |
| docs/milestones/milestone_N_plan.md | 一个复杂阶段的顺序、影响或独立审阅需要详细计划时；稳定编号，一阶段一份现行计划 | [编号计划](../templates/docs/milestones/milestone_1_plan.md) |
| TODO.md | 获准创建/正式初始化必须有效交付；后续按策略维护当前目标、行动、阻塞、下一步 | [当前行动](../templates/TODO.md) |
| DEVLOG.md | 获准创建/正式初始化必须有效交付；留有效结论及理由，无结论如实说明，不编造经验 | [维护记录](../templates/DEVLOG.md) |

蓝图不承载需求验收、排期、运行态或 Registry。设计引用确认需求；路线图安排选入的需求；计划引用需求、设计和阶段；TODO 链接当前包而不复制计划。README、DESIGN 和索引只摘要、链接其他职责正文。

## 固定栏目与按需增补

新建或获准整体重整时，保留模板的中文一级标题用途与二级栏目名称、顺序；通常细分到三级。项目名替换为真实名字。必填栏目可简写，无事项写“暂无”，未知不写成“不适用”；不留下空表或教学提示。小修改只动相关部分，已批准等价结构不强行改名。

普通正文按用户要求、既有文件语言和项目语言解析，默认简体中文；固定模板中文栏目属于本规约约定。用户明确要求其他语言时对应翻译栏目、保持职责顺序，不建立第二语言模板树。文件名、命令、代码、字段及品牌保持原文。

| 文档 | 条件性内容与位置 |
| --- | --- |
| README | 凭据与权限在准备条件；多端入口在安装或接入；接口参考、开发与贡献在日常使用与求助。涉及配置、更新、撤销安装时，在限制与许可前依次加配置与数据、更新与迁移、暂停、恢复与卸载，只保留适用项 |
| 蓝图 | 复杂旅程在场景/能力展开体验；收费或成本影响成立时在目标结果补商业目标；影响启动的条件写约束。不要加维护流水和排期 |
| 需求 | 跨文档引用才加稳定 R 编号；有取舍时加优先级和理由；多角色/分支配图，界面难讲清时配原型 |
| DESIGN | 接口、数据、部署在整体结构；交互、并发、安全在关键流程。独立详细说明仅保留导读，不再复制 |
| architecture | 接口、数据归属/生命周期、部署在结构；状态/事务在协作；并发、性能、安全在质量。没有相应机制不虚构 |
| roadmap | 当前阶段清晰，远期写方向与已知依赖；分支/并行复杂才加依赖图，真实日期/资源承诺才写对应字段 |
| 编号计划 | 每包有小结果、行动、依赖与判断；复杂依赖才配图，易误用命令才展开；运行或数据变更才补恢复安排 |

蓝图、需求、设计和架构开头简写状态及更新日期，必要时再加版本/范围；不为每份增加修订账本或固定状态字段。同步触发与需求变更由 [持续收敛](lifecycle-and-closeout.md) 维护。

## 一组教学样例

以下“清单检查工具”为虚构例子，R1/R2 已确认、M1 待实施、API 仅候选；不是本机实现或验证：

- 蓝图：减少交接材料时逐项翻目录的负担；API 是长期设想。
- 需求：R1 列出清单缺项，齐全显示“无缺失”；R2 读取失败明确报错，不返回“无缺失”；输入只读。
- 设计：入口处理参数和输出，读取函数解析输入，比较函数生成差异；单脚本已足够，不预拆多层。
- roadmap：确有跨包安排时，M1 规则正确、M2 命令行可运行、M3 新用户可完成首次任务；不是固定三个阶段。
- 当前计划：W1 样例与预期、W2 规则及正常/失败用例、W3 总体验证。每包立即同步说明，不先写完所有代码再补所有测试。
- TODO：只留当前包、阻塞与最近动作。DEVLOG 仅在形成有效经验时记录“暂不拆多层目录”的理由。
- M1 完成后确认 CSV 为 R3：更新需求及验收，安排后续包，形成独立阶段结果才新增里程碑；不把 M1 因新需求改为未完成。

## 可选专业说明

接口、数据、交互、操作、验收和重大决策提纲仍是候选，不擅自生成整套固定树。既有 [operations](../templates/docs/operations.md)、[evaluation](../templates/docs/evaluation.md) 和 [ADR](../templates/docs/adr/ADR-NNN.md) 仅作可选起点，按已采用的项目约定调整。

独立审查确需冻结快照才用 [Review Packet](../templates/docs/review-packet.md)；外部需要项目摘要才用 [Closeout Packet](../templates/docs/closeout-packet.md)。它们不成为现行事实或发布决定。

## 本地记录预检

先区分授权，再检查内容和记录策略：

1. 获准创建项目或正式初始化时，在项目根目录有效交付 TODO.md、DEVLOG.md；创建属于初始化任务，无需逐文件再请批。只读咨询、普通维护、仅采用技能不构成该授权，不自动补建或改 ignore。
2. 逐份读取现有文件。已有有效内容及原字节保留，仅补缺失文件，不重置、迁移或创建日期副本；已有空文件、教学占位或对象不可安全写入时，不擅自覆盖，列明无效处及必要处置，初始化未完成。
3. 新建 TODO 填真实当前目标、至少一个可执行行动、阻塞或“暂无”、下一步；DEVLOG 填实际有效维护结论与理由，无结论可写“当前无新增维护结论”。模板教学提示必须替换，不编造经验，不靠非空或文件存在判通过。
4. 新 Git 项目默认在现有 .gitignore 精确加入 `/TODO.md`、`/DEVLOG.md`，保留其他内容、避免重复，并实际核对未跟踪且被忽略。已有明确记录策略原样保留并按该策略验证；跟踪/忽略策略不明或与初始化要求冲突时停止报告未完成，不擅自取消跟踪、强行追加覆盖性 ignore、改权限或迁移记录。
5. 非 Git 项目仍须有效双文件，跟踪/忽略检查标“不适用”，不为验证擅自 `git init`。权限或策略无法满足时报告精确未完成项，不把一份成功写入说成初始化完成。
6. 初始化收尾读回根级路径、有效内容和适用的实际 Git 状态；两份都满足才报告完成。非初始化写记录前沿用已确认策略；缺失、已跟踪、未忽略或状态不明不自动修复。这项保护不适用于已授权初始化的缺失文件补齐。

记录不设固定条数。TODO 只保留当前工作与仍有用的近期结果；旧完成项不能机械转入 DEVLOG。DEVLOG 同一主题原位提炼，保留重要拒绝理由、必要未知和固定证据引用，长期事实进对应共享正文。
