# 项目结构与文档规约

创建、重整文档、判断唯一正文，或新增重要能力、职责/依赖变化、重构及目录/导航影响维护时，按任务读取对应章节。先复用现有等价来源，只补缺失且实际需要的职责；不把模板清单变成生成清单。以职责和读者任务组织，不以文件数、行数、上下文长度或模板数量拆分；普通小修不扩大为全仓考古。

## 文档职责与按需选择

minimal 覆盖持续项目的用户入口、项目蓝图、确认需求、必要设计与执行规则；获准创建/正式初始化必含根级 TODO.md、DEVLOG.md。standard 只增加需独立维护的详细架构、阶段安排或决策。runtime_integration 只增加当前真实涉及的运行、合同、安全、存储和集成层。根级 tmp/ 是各档位可写任务的共同目录要求，不计作文档模板。单篇专业说明不意味着铺开更高档位。

不要求逐职责裁剪表、固定字段、状态 Schema 或新报告。唯一事实来源、实际缺口与触发条件清楚即可。

下表同时列出文档职责与临时目录约定，先按所在目录层级从浅到深排列（根目录 → docs/ → docs/milestones/），同层按名称不区分大小写 A–Z 排序；目录条目末尾的 / 不计作额外层级。文档按各行条件建立，tmp/ 为可写任务必需的本地目录，MANUAL 仍为按需补充。

| 目标文件、目录或等价来源 | 职责与建立条件 | 模板 |
| --- | --- | --- |
| AGENTS.md | 采用项目执行规则时；只写局部差异和读取条件 | [执行规则](../templates/AGENTS.md) |
| DESIGN.md | 有设计时维护概要方案、UML 结构、功能/接口/数据与交付形态、实现位置及详细文档导读 | [概要设计](../templates/DESIGN.md) |
| DEVLOG.md | 获准创建/正式初始化必须有效交付；紧凑条目留有效结论及理由，记录多时按真实里程碑分组；无结论如实说明 | [维护记录](../templates/DEVLOG.md) |
| README.md | 持续项目的用户入口：用途、接入、首次使用、求助和限制 | [README](../templates/README.md) |
| tmp/ | 根级本地临时目录：可写任务开始时必须创建/复用，可控临时材料集中存放；Git 默认忽略 /tmp/。只读只核对，不作为长期正文或自动清空目标 | 无文档模板；[目录约定](#项目根临时目录) |
| TODO.md | 获准创建/正式初始化必须有效交付；后续按策略维护当前进度、里程碑位置、待办/问题、阻塞及下一阶段 | [项目进度与 TODO](../templates/TODO.md) |
| docs/BLUEPRINT.md | 新建持续项目的受跟踪蓝图：目标、用户、场景、核心能力和产品边界；旧项目复用完整等价来源 | [蓝图](../templates/docs/BLUEPRINT.md) |
| docs/MANUAL.md | 有可操作运行边界，需独立说明启动、停止、验证、回滚和排障时；README 保留首次使用入口 | [操作与运维手册](../templates/docs/MANUAL.md) |
| docs/PRD.md | 持续迭代的已确认有效需求、行为边界与验收；一次性任务复用现有明确要求 | [需求](../templates/docs/PRD.md) |
| docs/ROADMAP.md | 跨工作包的阶段、依赖与退出判断需要独立维护时；跨会话/机器本身不是理由 | [路线图](../templates/docs/ROADMAP.md) |
| docs/SAD.md | 简洁 DESIGN 已无法承载详细结构、协作与关键机制时 | [架构](../templates/docs/SAD.md) |
| docs/milestones/M{N}_PLAN.md | 一个复杂阶段的顺序、影响或独立审阅需要详细计划时；稳定编号，一阶段一份现行计划 | [编号计划](../templates/docs/milestones/M1_PLAN.md) |

BLUEPRINT 承载项目意图，不承载需求验收、排期、运行态或 Registry。DESIGN/SAD 引用 PRD 的确认需求；ROADMAP 安排选入的需求；M{N}_PLAN 引用需求、设计和阶段；TODO 链接当前包而不复制计划。README、DESIGN 和索引只摘要、链接其他职责正文。

## 模板与栏目约定

### 通用写法

- 新建或获准整体重整时保留模板中文标题的用途及二级栏目名称、顺序，通常只细分到三级；小修改保留有效等价结构。
- 项目名与教学提示替换为真实内容。必填栏目可简写，无事项写“暂无”，未知不写“不适用”，不留空表或占位。
- 普通正文按用户要求、既有文件语言和项目语言解析，默认简体中文。用户明确要求其他语言时翻译栏目并保留职责顺序，不建第二语言模板树。
- 文件名、命令、代码、字段与品牌保持原文。BLUEPRINT、PRD、DESIGN、SAD 开头简写状态和更新日期，版本/范围按需补，不增固定修订账本。

### 条件性内容

两表沿用层级优先、同层 A–Z 顺序。本表只说明内容放哪里；建立条件看前表，详细格式看下方分组。

| 文件或目录 | 条件性内容与位置 |
| --- | --- |
| DESIGN.md | 概要方案放正文；详细机制、决策和验证只摘要并导读，图示及目录树按下方要求 |
| README.md | 凭据/权限放准备条件，多端入口放接入，参考链接放日常使用与求助；配置/数据、迁移、暂停恢复和卸载按需放在限制与许可前 |
| tmp/ | 可控临时材料集中存放；工具受限说明例外，正式资产原位保留，现有内容不自动清空 |
| docs/BLUEPRINT.md | 复杂旅程展开在场景/能力；成本影响成立时补商业目标，关键前提放约束；功能验收归 PRD，排期归 ROADMAP/编号计划 |
| docs/MANUAL.md | 按实际环境写前提、启动/停止、验证、回滚与排障，只保留真实层和恢复点；README 保留首次使用入口，步骤不推导运行授权 |
| docs/PRD.md | 跨文档引用才加稳定 R 编号；取舍补优先级/理由，多角色或分支按需配图，难以说明的界面配原型；候选留待确认 |
| docs/ROADMAP.md | 当前阶段写清，远期保留方向与依赖；并行复杂才配依赖图，真实日期/资源承诺才写对应字段，不展开工作包细节 |
| docs/SAD.md | 接口、数据归属/生命周期和部署放系统结构；状态/事务放关键协作；并发、性能、安全放质量策略；已有 ADR 只摘要链接 |
| docs/milestones/M{N}_PLAN.md | 每包写小结果、行动、依赖与判断；复杂依赖才配图，易误用命令才展开，运行或数据变更才补恢复安排；阶段退出独立判断 |

表中使用当前文件/目录名，tmp/ 不作为文档真源。同步触发由[持续收敛](lifecycle-and-closeout.md#每包同步与轻巡)维护。

### README 展示

- 使用[展示模板](../templates/README.md)，六项核心职责顺序不变；二/三级标题各带一个相关 Emoji，首屏居中，提供稳定导航、表格、命令与结果，图片/FAQ 按需选用。
- 公开 GitHub 仓库才启用徽章与可选 Star History，后者始终最后。无真实图片、Release、许可文件或文档时移除对应入口，填实全部变量，不生成贡献或免责声明栏目。
- 许可状态与文件入口分开：无许可文件就删徽章/文件链接，正文仍说明真实许可状态，未知如实写。保留真实限制；样式不传播到其他模板，用户指定风格时按要求调整。

### DESIGN 概要与 UML

- 保留七项概要栏目：设计概要、整体结构与模块职责、核心功能与实现概览、接口与数据概览、代码与目录组织、交付与运行形态、设计文档导读；不展开逐函数细节或验证/决策流水。
- 新建或获准整体重整时必须至少一张真实 UML 结构图，默认组件图。普通小改不自动补绘；组件/部署等架构类图保留 Figma 可编辑原稿及 PNG/SVG，缺工具或授权标未完成。
- 协作、对象、生命周期和部署关系按需补相应 UML 视图，不要求全套。没有独立接口、数据或服务如实简写，minimal 不因此增加详细架构或空文档。
- 代码与目录组织采用带职责注释的 text 树状结构，沿用实际路径；目录树不替代 UML。图名、关系、现行/拟议边界和引用随设计同步。图示选型与审阅见[工程图](zh-CN.md#工程图)。

### TODO 与 DEVLOG

- TODO 保留“当前进度、里程碑总览、当前里程碑 TODO、下一里程碑”四项栏目，说明位置、差距、待办/问题、阻塞及后续；已有计划只摘要链接，不展开执行教程。
- 未划分里程碑如实说明，不虚构编号、未来承诺或完成百分比；旧完成项不机械转入 DEVLOG。
- DEVLOG 保留“有效维护记录”一项二级栏目，默认用“日期｜主题”的加粗列表紧凑条目写结论与理由，依据/影响按需补。查找困难才按真实里程碑用三级分组，不给单条加子标题或固定字段；不使用 Emoji。
- 两者不使用 Emoji，也不设固定条数；同题原位提炼，保留重要拒绝理由、必要未知、固定证据及结论形成时的边界。事件同步见[每包同步](lifecycle-and-closeout.md#每包同步与轻巡)。

### 教学样例

以下“清单检查工具”为虚构例子，R1/R2 已确认、M1 待实施、API 仅候选；不是本机实现或验证：

- BLUEPRINT：减少交接材料时逐项翻目录的负担；API 是长期设想。
- PRD：R1 列出清单缺项，齐全显示“无缺失”；R2 读取失败明确报错，不返回“无缺失”；输入只读。
- DESIGN：入口处理参数和输出，读取函数解析输入，比较函数生成差异；单脚本已足够，不预拆多层。
- ROADMAP：确有跨包安排时，M1 规则正确、M2 命令行可运行、M3 新用户可完成首次任务；不是固定三个阶段。
- M{N}_PLAN：W1 样例与预期、W2 规则及正常/失败用例、W3 总体验证。每包立即同步说明，不先写完所有代码再补所有测试。
- TODO：摘要 M1 的位置与差距，列当前包待办、发现的问题及后续方向。DEVLOG 仅在形成有效经验时用紧凑条目记录“暂不拆多层目录”的理由。
- M1 完成后确认 CSV 为 R3：更新需求及验收，安排后续包，形成独立阶段结果才新增里程碑；不把 M1 因新需求改为未完成。

### 可选专业说明

- 接口、数据、交互、操作、验收和重大决策按实际需要展开，不生成整套固定树。操作用可选 [MANUAL](../templates/docs/MANUAL.md)，详细架构用 SAD；重要决定使用独立 [ADR](../templates/docs/adr/ADR-NNN.md)，保留背景、决定、备选与后果。
- 已采用 ADR 约定且形成重要长期架构决定时才用决策提纲。新文件如 docs/adr/0001_decision_title.md 遵守 docs 命名，既有路径不自动迁移；短期行动、单次失败及未决候选仍归 TODO、DEVLOG、PRD 或相关设计。
- 不预设独立评估文档，比较与试用证据留对应正文；取消模板不取消必要验证、未知或证据边界，已有消费者材料不因此搬动或删除。
- 审查快照与交付摘要按实际接收需要整理，不预设模板；[冻结与退役](lifecycle-and-closeout.md#审查交付与退役)由生命周期参考维护。

## 路径、命名与导航

- 新项目多词用下划线，品牌与大小写遵守项目约定。
- 根级 README.md、AGENTS.md、DESIGN.md、TODO.md、DEVLOG.md 以及 Skill 的 SKILL.md 保留生态入口名。
- 新普通 docs 文件和多词目录用小写 snake_case，扩展名 .md；目录索引 README.md 是例外。
- BLUEPRINT 默认 docs/BLUEPRINT.md，PRD 默认 docs/PRD.md；默认不新建根级 BLUEPRINT.md，也不复制第二份蓝图正文。
- 编号计划采用 docs/milestones/M1_PLAN.md、M2_PLAN.md，编号稳定；milestones 可只含当前一份计划，不额外建索引。
- 代码、测试、锁文件、工具入口遵守语言与工具生态；技能标识 swift-cycle 保持连字符。
- 图及长期说明用稳定用途名原位维护，不堆日期副本、new/old/final2，不套 source-版本-提交号/。
- 已有稳定路径不因整理自动迁移；旧命名偏差需批准的文档整理包，统一修复引用，不复制第二正文。

固定专业文档名例外：docs/PRD.md、docs/SAD.md、docs/BLUEPRINT.md、docs/ROADMAP.md、docs/MANUAL.md；编号计划用 M{N}_PLAN.md，N 是稳定正整数，一阶段一份现行计划。新名称仅作创建默认值，已有完整等价来源继续复用。

小项目由 DESIGN 承载必要设计与详细文档导读。只有查找困难时才增加 docs 首页。索引写短说明与实际链接，按需要注明用途、读者或状态，不固定四列表格；不复制事实正文。tutorial、how-to、reference、explanation 可帮助选择写法，不是另一套必建目录。

docs 首页与 ADR 索引没有固定模板；确需独立导航时直接按现有内容组织短说明与实际链接，不因目录存在自动建立 README，也不要求索引的状态表或修订账本。

单篇说明通常留 docs 根；同类内容需独立导航或附件组才建职责目录，如 contracts、operations、adr。正式事实保持唯一正文，概要和导读引用它。当前源码、安装、运行数据、恢复点分开；开发材料不全量装入 Skill。

## 代码组织与能力复用

小脚本可用函数区分入口、规则和外部接入。需要打包、导入或独立维护时再用 src/ 等布局；前后端、服务、共享模块只有真实独立职责才拆目录。按语言命名、格式、类型及错误约定实现，注释解释理由和边界。

共用逻辑确有共同含义且降低维护成本才抽取，允许尚无稳定共性的少量重复。不要为未来设想预建框架、对称空目录或完整设计系统。

触发结构变化时，先在受影响路径及已知入口有界查找既有实现、调用者和测试；记录查找边界及复用、扩展或新建理由，“未找到”不等于“不存在”。明确受影响模块负责/不负责什么、允许依赖及文件落点；有意例外说明理由，不强制统一树或空框架。

在既有 DESIGN/SAD 的相应栏目补受影响关键能力的“能力 → 实现 → 调用入口 → 测试 → 既有证据”定位，用短文、链接或必要小表即可；暂无实现/测试/证据如实标明。证据只链接，不复制第二套状态、功能账本或全函数登记。仅维护当前影响面，不要求登记所有能力。

重构前明确保留的正常、失败及相关跨入口行为，用相关回归保护；文件/行数更少不等于质量更好。结构整理不自动获得清理临时产物或删除资产的权限。

## 本地记录与初始化预检

本节的补建和 ignore 规则只针对 TODO.md、DEVLOG.md 本地记录；根级 tmp/ 另按下方独立约定处理。先区分授权，再检查内容和记录策略：

1. 获准创建项目或正式初始化时，在项目根目录有效交付 TODO.md、DEVLOG.md；创建属于初始化任务，无需逐文件再请批。只读咨询、普通维护、仅采用技能不构成该授权，不自动补建或改 ignore。
2. 逐份读取现有文件。已有有效内容及原字节保留，仅补缺失文件，不重置、迁移或创建日期副本；已有空文件、教学占位或对象不可安全写入时，不擅自覆盖，列明无效处及必要处置，初始化未完成。
3. 新建 TODO 填真实当前目标、至少一个可执行行动、阻塞或“暂无”、下一步；DEVLOG 填实际有效维护结论与理由，无结论可写“当前无新增维护结论”。模板教学提示必须替换，不编造经验，不靠非空或文件存在判通过。
4. 新 Git 项目默认在现有 .gitignore 精确加入 `/TODO.md`、`/DEVLOG.md`，保留其他内容、避免重复，并实际核对未跟踪且被忽略。已有明确记录策略原样保留并按该策略验证；跟踪/忽略策略不明或与初始化要求冲突时停止报告未完成，不擅自取消跟踪、强行追加覆盖性 ignore、改权限或迁移记录。
5. 非 Git 项目仍须有效双文件，跟踪/忽略检查标“不适用”，不为验证擅自 `git init`。权限或策略无法满足时报告精确未完成项，不把一份成功写入说成初始化完成。
6. 初始化收尾读回根级路径、有效内容和适用的实际 Git 状态；两份都满足才报告完成。非初始化写记录前沿用已确认策略；缺失、已跟踪、未忽略或状态不明不自动修复。这项保护不适用于已授权初始化的缺失文件补齐。

记录格式、保留边界与事件同步分别见上方 [TODO 与 DEVLOG](#todo-与-devlog) 和[持续收敛](lifecycle-and-closeout.md#每包同步与轻巡)。初始化的目标/行动/阻塞/下一步是信息职责，不强制沿用旧栏目字面名称。

## 有界整理与临时材料回收

### 有界整理

整理已获授权时，在当前包内核对目标结构、保留项及入链，做可追溯移动和链接修正，再检查唯一正文、相关验证与 git diff --check。不需要逐文件请批。变更权威、删除 tracked 资产、消费者不明或越界时才请求决定。

每包聚焦受影响内容，消除明确重复并轻巡关联入口；反复堆积影响维护或用户明确要求时才扩大整体整理。无用过程不搬进 history、archive 或 ZIP。

### 项目根临时目录

- **可写任务**：采用、接管、初始化与后续维护开始时，必须在确认的项目根创建或复用 tmp/，核对真实目录未越界并保留已有内容。
- **只读任务**：只核对缺口，不创建目录、不改 ignore；咨询不推定持久采用。采用/初始化收尾读回目录及适用 Git 状态，未满足明确未完成，不能以系统临时目录代替达标。
- **Git 项目**：在现有 .gitignore 精确忽略 /tmp/，保留其他内容；已有效忽略就不重复添加，确认临时内容未跟踪，不新增 .gitkeep。
- **非 Git 项目**：同样须有根级 tmp/，忽略检查不适用，不为此 git init。
- **现场冲突**：同名文件、越界重定向、不可写、已有跟踪内容或策略冲突均保留现场并报告；不覆盖、不迁移资产、不取消跟踪或擅自改权限。
- **临时输出**：可控草稿、一次性脚本、隔离 fixture、下载暂存、检查输出和中间文件放 tmp/，可按任务建子目录，不另建 AI 产物树。
- **路径设置**：优先用工具目录参数；必要时仅为一次命令或子进程设置 TEMP/TMP/TMPDIR，核对实际路径，作用结束即恢复。尽量减少额外 C 盘写入，项目本在 C 盘也不因此迁移。
- **工具例外**：必须用系统临时位置、输出受限或位置不可控时，说明实际路径和原因，不宣称所有输出都在项目内。
- **作用域与保留**：不改用户/系统级 TEMP/TMP、全局缓存或其他项目，不迁移旧缓存或扫描清理 C 盘。源码、持久数据、构建输入、交付物及必要证据按职责原位维护；临时结果长期保留时只晋升必要结论或资产并更新引用，不自动清空 tmp/，集中存放不授予删除权限。

### 临时材料与回收

临时文件按上述根级 tmp/ 约定落地。缓存、一次性脚本、中间输出只成为回收候选；build/artifacts 名字不决定去留。用途、使用者、许可及生命周期一致才合并。

回收先核对精确绝对路径、使用者、恢复价值、符号链接/ReparsePoint 边界及当次授权。源码、补丁、构建输入、锁文件、必要测试、安装内容、用户数据和恢复点默认保留；固定合同引用的材料按合同保留路径与身份。

Windows 用回收站，其他环境用核对后的可恢复方式；机制不明、仍被使用或路径越界则保留，不永久删除或清空回收站。Git 历史不能恢复忽略记录、用户数据或运行恢复点。详见 [生命周期](lifecycle-and-closeout.md)。
