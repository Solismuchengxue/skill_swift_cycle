# 治理与证据边界

涉及多个事实来源、长期知识、复合状态、多提交或源码/运行态关系时，仅读取当前风险相关部分。

## 治理基线

非简单治理、迁移、替换、重组或跨交付层工作，确需可靠前后比较时，记录：

- 当前范围与唯一事实来源；
- 相关身份及保留项；
- 已确认事实与待确认项；
- 证据来源与时间。

当前状态和目标状态分开。范围、身份或正文职责变化时刷新基线或标失效；简单局部修改不建专用基线文件。

## 知识晋升

本地 TODO/DEVLOG 用于捕获行动和经验。长期结论形成后写回职责对应的共享正文：

| 信息 | 去向 |
| --- | --- |
| 短期行动、单次失败、当前会话信息 | 留在 TODO 或 DEVLOG，不晋升 |
| 确需独立维护的阶段或长期承诺 | 复用 ROADMAP、编号计划、Issue 或共享来源；跨会话/机器本身不触发新文档 |
| 长期架构约束或重要权衡 | DESIGN/SAD、ADR 或既有决策文档 |
| 后续需引用的已验证事实 | 先复用已有结论，确需独立维护才建证据文档 |
| 迁移结果 | 对应现有说明，确需独立维护才建迁移文档 |
| 用户可见事实 | README 或用户文档 |

晋升后以共享正文为准，本地只留状态或链接。

## 状态拆分

标签同时回答实现、实验、质量、发布等问题时，先列出它实际回答什么，再拆项目确实跟踪且关闭证据不同的生命周期。总体状态仅作派生摘要。

不规定固定字段、字段名或状态 Schema；关闭一个生命周期不能静默关闭另一个。

## 提交边界

多提交、混合目的修改、顺序依赖或独立审查历史确有需要时，暂存前说明：

- 单一意图；
- 精确路径或代码差异片段；
- 依赖与预期中间状态；
- 独立验证与回退。

简单单提交核对暂存范围即可。已有用户改动和本地维护记录默认不进入提交。

## 源码与运行态

只区分实际存在的源码、制品、部署运行态和活动消费者：

- 各层有独立事实、授权与关闭证据；
- 源码通过不证明制品或运行态，部署成功不证明消费者已切换；
- 未检查层保持未验证；
- 身份误配会影响结论时才建必要身份矩阵。

Git 文件模式与安装权限分开判断。包装层或字段映射来自权威约定，避免检查器与 manifest 共用同一错误派生值形成假通过。

## 工具与外部作用域

- 项目本地配置尽量缩小影响范围。
- 共享基础设施记录影响面、兼容性、所有权与回滚。
- 用户/系统级配置是外部部署状态，须单独授权。
- 工具产物先判断是源码、缓存、证据还是运行数据，再决定跟踪、刷新或退役。

工具先复用已有能力，按问题选择；工具表不证明已安装、连接或采用。安装/配置及云端发送材料核对授权，发送秘密或私人材料须有明确授权；正常已授权调用不重复请批。

## 文档新鲜度

同步时机与目标正文按[每包同步](lifecycle-and-closeout.md#每包同步与轻巡)执行；本节检查证据是否仍支持当前说法：

- 状态、数量、身份、待办和 UNKNOWN 是否仍有效；
- DESIGN 导读、标题、链接、图源/导出图及已有记录是否可用；
- 发现过时或矛盾内容时更新、标过期、替代或退役，不静默保留矛盾。

审查快照沿用[交付后冻结规则](lifecycle-and-closeout.md#审查交付与退役)，不改成现行真源，也不为检查新增固定修订账本。

## 独立审查

审查目标、架构、边界、职责与文档是否符合事实，优先使用直接、最小、决定性证据。不默认要求全仓 SHA、多份重复 manifest、同源反演的重复证明或无关格式微审计。

哈希、manifest、权限或格式本身属于合同或身份声明时，才对该局部核对。未运行检查不得写成通过。

## 项目外边界

Swift Cycle 可输出有界项目事实供协作使用，不创建或替代上层任务路由、容量管理、独立验收、组织状态、Registry、跨部门治理或跨项目运行授权。

外部决定由对应主体作出，项目文档不能自行宣称接受、激活或部署。
