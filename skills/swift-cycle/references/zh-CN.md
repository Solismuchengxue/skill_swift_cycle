# 中文表达、图示与用户交付

需要图示、交互、用户上手或汇报时读取；不复制主工作流。

## 语言与术语

普通对话先服从用户要求，再服从当前语言；文件先服从明确要求，既有文件沿用主语言，新文件用项目语言，未指定默认简体中文。固定模板栏目与语言例外见 [模板与栏目约定](document-profiles.md#模板与栏目约定)。文件名、代码、命令、路径、字段、标准状态及品牌保持准确原文，不堆中英同义双写。

| 术语 | 中文职责 |
| --- | --- |
| Swift Cycle | 快速螺旋；标识与调用保留 swift-cycle |
| BLUEPRINT | 项目蓝图：目标、愿景、用户、场景、核心能力和产品边界 |
| PRD | 产品需求文档：已确认且仍有效的行为、约束和验收 |
| DESIGN / SAD | 概要设计与详细导读 / 按需独立维护的详细架构 |
| MANUAL | 按需维护的操作与运维手册，操作步骤不等于运行授权 |
| ADR | 独立架构决策记录：背景、决定、备选和后果 |
| ROADMAP / milestone | 路线图 / 里程碑：阶段结果、依赖和完成判断 |
| work package | 工作包：实现、必要验证和说明同步组成的小结果 |
| adoption / document profile | 采用 / 文档档位 |
| initialization / local records | 初始化 / 本地记录：获准创建或正式初始化须有效交付根级 TODO.md、DEVLOG.md；仅采用不推定初始化，操作边界见文档职责 |
| knowledge promotion / state separation | 知识晋升 / 状态拆分 |

先结论后理由，一段一个重点；对象、动作、结果明确。步骤用列表，比较用表格，复杂关系配图。一级标题一个，固定栏目用二级，通常只细分三级；标题、正文、列表、表格、代码块之间留空行，关键前提和操作不折叠。

用“增加格式只需改读取模块”代替“高扩展性”；用“本地用例通过，设备尚未验证”代替“已验证应该没问题”。设想、示例、实现、验证分开；未查明写待确认、未知或 NOT_VERIFIED，不装作不适用。

## 工程图

只有关系用短文/表格难以讲清时配图，一图一个主要关系。目录树和列表不能代替系统关系。

| 读者问题 | 表达 |
| --- | --- |
| 系统环境、边界、模块组成 | Figma 上下文/结构图 |
| 主机、进程、存储与网络位置 | Figma 部署图 |
| 调用顺序、等待与失败 | 时序图 |
| 分支、状态与恢复 | 流程图、状态图 |
| 处理路径、实体关联 | 数据流图、实体关系图 |
| 阶段/工作包依赖 | 依赖图；有真实日期约束才用甘特图 |

架构图指定 Figma 绘制与维护，保留可编辑节点、文字和连线，不能将整图贴成单一位图充当图源；在现有资源位置导出 PNG/SVG 嵌入正文，并提供可编辑原图入口。Figma 不可用时报告架构图未完成，不用 Mermaid 替代或宣称完成。其他流程、时序、状态与计划图可用 Mermaid、PlantUML 或既有工具。

[DESIGN 概要模板](../templates/DESIGN.md)按设计概要、模块结构、核心功能、接口/数据、代码组织、交付形态、详细导读组织，不使用 Emoji。新建或获准整体重整须至少一张对应项目的真实 UML 结构图，默认组件图；普通小改不自动补绘。时序/活动、类、状态和部署图按实际关系需要加入，不凑齐全套。图与正文/实现名称及现行/拟议部分一致；缺必要原稿、导出图或工具条件保持未完成，不以模板占位算交付。

布局由项目关系与用户审美选择，不固定容器式包裹、方向、层数或对称。分组只表示真实包含/责任；普通概念与关系标签用中文，同类节点一致，对齐和留白清楚，连线减少交叉并说明方向。颜色语义稳定，信息不只依赖颜色。

审阅正文实际宽度下的文字、连线、裁切和对比，拥挤则拆图；核对图与正文/实现名称、关系、现行/设想及权限边界。未实际预览不声称渲染良好。无图不预建图片目录。

## 界面与交互

围绕主要用户任务安排动作、结果和限制，技术详情按需展开。同类控件及文案一致，中文标签说明动作；长路径/文本/代码能换行、滚动或复制，不挤走输入与按钮。样式、配色、字体、圆角、动效按项目选择，不强制完整设计系统。

在支持的屏幕、缩放、输入方式下走查主要操作、键盘、焦点、对比、退出和触控；采用无障碍标准后按相应目标验证。错误靠近字段，保留适合保留的输入；秘密使用安全输入，不进聊天、日志或命令参数。

等待显示真实阶段，成功给结果位置，失败给原因和处理办法，取消/部分完成说明已执行内容。按需处理取消、超时、中断和重复提交；连续步骤复用确认信息，普通可逆操作不反复确认。高成本流程可先原型，设计稿明确为设想。

命令行菜单、动作、退出和中文摘要清楚，无色终端也可读；有机器调用才提供稳定结构化输出与退出码。用户可操作的 AI 功能说明输入用途、结果限制、修改方式，并按需区分草稿、采用与执行。

## README 与汇报

用户能从 README 完成首次任务、判断成功、处理常见失败，并找到适用的更新、恢复、卸载入口。命令可复制，执行位置、Shell、权限和替换值明确；首装、更新和已有数据处理分别说明。公开入口不依赖私人路径、秘密或临时材料；提供离线说明时须与实际安装版本一致，源码说明不能冒充已安装版本。

名称与开始入口醒目，能力用短句；图形界面用真实净化截图，命令行用菜单/输入输出，库和 Skill 用调用例子。横幅、徽章、动图按需要添加，状态真实；GitHub 展示不依赖任意 CSS/JavaScript。真实配置和样例分开，交付所需构建输入、锁文件、来源和许可保留。

README 的[展示模板](../templates/README.md)提供填写起点；展示样式、按需栏目与填充规则统一按[模板与栏目约定](document-profiles.md#模板与栏目约定)执行。

[TODO](../templates/TODO.md)展示项目当前进度、里程碑位置与差距、交付待办、发现的问题/阻塞和下一阶段；已有计划只摘要并链接，无里程碑如实说明，不虚构百分比。[DEVLOG](../templates/DEVLOG.md)用“日期｜主题”的紧凑条目保留结论与理由，依据和影响按需补，记录多时按真实里程碑分组，不给每条加子标题。两者不使用 Emoji；实质进展及时更新 TODO，有效经验才进 DEVLOG，不复制完成流水。

进展说发现、影响、下一步；请求决定说事项、原因、推荐与代价；交付说实际结果、入口、验证、限制和下一步。耗时工作及时报告变化，不播报每条命令，不报无依据百分比。最终答复独立可读，链接可点击；按接收方需要选现有 Markdown、表格、预览或演示工具，不为形式堆报告。
