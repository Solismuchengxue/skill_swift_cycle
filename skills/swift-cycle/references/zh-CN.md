# 中文表达、图示与用户交付

需要语言表达、图示、交互、用户上手或汇报时读取。文档职责、栏目和维护时机分别见[统一规约](document-profiles.md)与[持续收敛](lifecycle-and-closeout.md)。

## 语言与术语

对话按用户要求和当前语言；文件按明确要求、既有主语言、项目语言依次判断，未指定默认简体中文。固定栏目及语言例外见[模板约定](document-profiles.md#模板与栏目约定)。

文件名、代码、命令、路径、字段、标准状态和品牌保持准确原文。普通概念用中文，不堆中英同义双写。

| 术语 | 中文职责 |
| --- | --- |
| Swift Cycle | 快速螺旋；标识与调用保留 swift-cycle |
| BLUEPRINT | 项目蓝图：目标、愿景、用户、场景、核心能力和产品边界 |
| PRD | 产品需求文档：已确认且仍有效的行为、约束和验收 |
| DESIGN / SAD | 概要设计与详细导读 / 按需独立维护的详细架构 |
| MANUAL | 按需维护的操作与运维手册，操作步骤不等于运行授权 |
| ADR | 独立架构决策记录：背景、决定、备选和后果 |
| ROADMAP / milestone | 路线图 / 里程碑：阶段结果、依赖和完成判断 |
| work package | 工作包：实现、必要验证和说明同步组成的小结果 |
| adoption / document profile | 采用 / 文档档位 |
| initialization / local records | 初始化 / 本地记录：获准创建或正式初始化须有效交付根级 TODO.md、DEVLOG.md；仅采用不推定初始化，操作边界见文档职责 |
| knowledge promotion / state separation | 知识晋升 / 状态拆分 |

先结论后理由，一段一个重点，明确对象、动作和结果。步骤用列表、比较用表格、复杂关系配图；标题、正文、列表、表格和代码块间留空行，关键前提与操作不折叠。

用具体行为代替“高扩展性”等空泛评价。设想、示例、实现、验证分开，未查明写待确认、未知或 NOT_VERIFIED，不当作不适用。标题与栏目层级按[通用写法](document-profiles.md#通用写法)执行。

## 工程图

先按场景判断是否必须配图，再选表达方式：

| 场景 | 配图要求 |
| --- | --- |
| 新建或获准整体重整 DESIGN | 必须至少一张对应实际项目的真实 UML 结构图，默认组件图；文字能讲清也不免除此要求 |
| 普通小改 | 不自动补绘或整体重整旧 DESIGN，核对受影响内容与已有图的一致性 |
| 其他图示 | 关系用短文/表格难以讲清时配图，一图表达一个主要关系 |

| 读者问题 | 表达 |
| --- | --- |
| 系统环境、边界、模块组成 | Figma 上下文/结构图 |
| 主机、进程、存储与网络位置 | Figma 部署图 |
| 调用顺序、等待与失败 | 时序图 |
| 分支、状态与恢复 | 流程图、状态图 |
| 处理路径、实体关联 | 数据流图、实体关系图 |
| 阶段/工作包依赖 | 依赖图；有真实日期约束才用甘特图 |

- 架构图指定 Figma，保留可编辑节点、文字与连线；整图位图不能充当图源。在既有资源位置导出 PNG/SVG 嵌入正文，提供可编辑原图入口。
- Figma 或必要授权不可用时标架构图未完成，不用 Mermaid 替代或宣称完成。非架构流程、时序、状态和计划图可用 Mermaid、PlantUML 或既有工具。
- UML 时序/活动、类、状态和部署视图按真实关系选用，不凑全套；DESIGN 栏目见[概要与 UML](document-profiles.md#design-概要与-uml)。目录树不替代系统关系，模板占位不算实际绘图。
- 布局服从真实关系与用户审美，不固定容器、方向、层数或对称。分组表达包含/职责，中文概念标签一致，留白、对齐、连线方向及颜色语义清楚，不只靠颜色传递信息。
- 在正文实际宽度预览文字、连线、裁切与对比，拥挤则拆图；核对名称、关系、现行/拟议及权限边界。未预览不声称渲染良好，无图不预建图片目录。

## 界面与交互

- 围绕用户主要任务组织动作、结果与限制，技术细节按需展开。同类控件/文案一致，中文标签说明动作；长路径、文本、代码可换行、滚动或复制，不挤走输入与按钮。
- 样式、字体、配色、圆角和动效按项目选择，不强制完整设计系统。支持的屏幕、缩放和输入方式需走查主要操作、键盘、焦点、对比、退出及触控；采用无障碍标准后按目标验证。
- 错误靠近字段，保留适合保留的输入；秘密使用安全输入，不进聊天、日志或命令参数。
- 等待显示真实阶段，成功给结果位置，失败说明原因与处理办法，取消/部分完成说明已执行内容。按需处理超时、中断和重复提交，连续步骤复用确认信息，普通可逆操作不反复确认。
- 高成本流程可先原型并标设想。命令行有清楚菜单、动作、退出和中文摘要，无色终端也可读；机器调用才需稳定结构化输出与退出码。
- 可操作的 AI 功能说明输入用途、结果限制、修改方式，按需区分草稿、采用和执行。

## README 与汇报

README 应让用户完成首次任务、判断成功、处理常见失败并找到适用的更新、恢复和卸载入口：

- 命令可复制，执行位置、Shell、权限和替换值明确；首装、更新与已有数据分开说明。
- 公开入口不依赖私人路径、秘密或临时材料；离线说明对应实际安装版本，源码说明不能冒充安装状态。
- 名称、开始入口和能力清楚；用真实净化截图、菜单/输入输出或调用例子展示。徽章、横幅和动图按需使用，状态真实，不依赖任意 CSS/JavaScript。
- 配置与样例分开，交付所需构建输入、锁文件、来源与许可保留。

README 的[展示模板](../templates/README.md)提供填写起点；样式、按需栏目和填充规则统一见[模板与栏目约定](document-profiles.md#模板与栏目约定)。[TODO](../templates/TODO.md)与[DEVLOG](../templates/DEVLOG.md)的格式和分工见[记录约定](document-profiles.md#todo-与-devlog)。

进展说发现、影响和下一步；请求决定说事项、原因、推荐与代价；交付说结果、入口、验证、限制和下一步。耗时工作及时报告变化，不播报每条命令或无依据百分比。最终答复独立可读、链接可点，按接收方选现有表达工具。
