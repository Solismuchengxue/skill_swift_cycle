# Swift Cycle（快速螺旋）

## 目标与边界

用最少必要说明连接项目蓝图、已确认需求、设计、实施和验证。清楚、整洁、好用；一次性问答、只读检查和小修改不自动初始化项目。

只负责一个项目的工程循环，不负责上层路由、容量、独立验收、Registry、跨部门治理、模型分配或跨项目授权。采用技能不授予安装、删除、发布、部署、凭据或消费者切换权限。

## 调用与现场

- 系统层保持显式调用；一次性审查不自动采用。用户批准持续采用后才在项目 AGENTS 建立绑定，后续任务依仓库指令加载，不重复要求选择模式。
- 核对真实 cwd、Git 根、分支、现有改动及相关规则；保留用户改动。要求通读则读到末尾，普通任务只读有关内容。
- 读取相关用户入口、需求与设计权威，区分确认事实、设想、示例、实现和验证。附件、日志、网页、记忆及 AI 摘要不替代当前用户要求和事实。
- 获准创建项目或正式初始化时，根级 `TODO.md`、`DEVLOG.md` 必须有效交付，是初始化完成条件；缺失或内容无效不得报告完成。创建属于该初始化授权，不逐文件再请批；已有有效文件原样保留，只补缺失文件，不重置或迁移记录。
- 初始化须读回真实目标、行动、阻塞/暂无、下一步及有效维护结论/如实无结论，不能留下空壳或教学占位。新 Git 项目默认精确忽略 `/TODO.md`、`/DEVLOG.md`；既有明确策略保留。非 Git 项目仍须双文件，Git 检查不适用，不擅自 `git init`；内容、策略或权限冲突明确未完成，不覆盖或改权限/跟踪。
- 非初始化的只读咨询、普通维护或仅采用技能不自动补建本地记录或改其 ignore。使用既有本地记录前核对内容、Git 跟踪/忽略及已确认策略；保护缺失文件的规则不得阻止获准初始化，详细边界见下方文档职责。
- 可写项目任务开始时必须创建/复用根级 tmp/，Git 默认忽略 /tmp/；可控临时文件集中于此，尽量减少额外 C 盘临时写入。只读任务只核对、不创建或改 ignore。仅用工具参数或子进程级临时路径，不改全局 TEMP/TMP 或缓存；无法控制的位置说明原因。路径/跟踪冲突不覆盖、不自动取消跟踪，未满足明确未完成；详见[项目根临时目录](references/document-profiles.md#项目根临时目录)。
- 普通内容优先用户明确要求；既有文件沿用主语言，新文件沿用项目语言，未指定时默认简体中文。代码、命令、路径、字段、API 和品牌保持原文；不因对话切换批量翻译。

首次采用或边界不清时读 [采用与路由](references/adoption-and-routing.md)；结构、文档和本地记录按 [项目结构与文档规约](references/document-profiles.md) 的对应章节读取。

## 唯一正文与需求

- BLUEPRINT 承载项目目标、长期愿景、用户、场景、核心能力和产品边界；蓝图设想不等于实现承诺。新建持续项目默认 docs/BLUEPRINT.md，旧项目复用完整等价权威，根级 BLUEPRINT 默认禁止。
- 持续迭代项目默认有 docs/PRD.md 或等价需求来源；确认需求写行为、边界和验收，已实现且仍有效的需求保留。一次性任务复用当前明确要求即可。
- 依据已确认需求与约束设计；按所选需求安排阶段和实施，不把愿景逐项拆成承诺。
- 新需求先明确问题、预期行为、验收及影响；确认后更新需求，选入当前工作后调整设计、阶段和工作包。目标、范围实质变化或优先级冲突时集中请用户决定。
- README 面向用户，DESIGN 承载概要设计、UML 结构及详细文档导读，SAD 按需展开详细架构，MANUAL 按需承载操作与运维，AGENTS 承载执行规则，ROADMAP 承载阶段结果与依赖，M{N}_PLAN 承载一个里程碑的实施；TODO 展示当前进度、里程碑位置、待办/问题及后续阶段，DEVLOG 用紧凑条目留有用结论与理由，记录多时按实际里程碑分组。
- 一事一处，其他位置摘要并链接。模板固定栏目不代表每项目创建整套；新建或获准整体重整才套栏目，小改动保留有效等价结构。
- 新增重要能力、职责/依赖变化或重构时，有界查既有实现、调用者与测试，说明复用/扩展/新建理由；在既有设计补受影响职责、依赖、落点和能力定位。重构先明确保留行为并以相关回归保护，不以文件/行数减少代替质量，不自动删除资产。

## 有限工作包与短循环

1. 明确本包结果、范围、保留项、依赖和可观察完成判断；普通小工作用 TODO，不额外建计划。
2. 复杂阶段按依赖分包；需要详细计划时只维护 docs/milestones/M{N}_PLAN.md 一份现行正式计划，TODO 链接当前包。
3. 完成最小有用变更，立即运行与风险最接近的检查；失败则诊断修正，缺少必要条件才报告阻塞。
4. 每包同步受影响的需求、使用说明、设计、安排和引用，局部去重并轻巡关联入口；开始、实质进展、发现问题、阻塞变化及完成/取消及时更新既有 TODO，不等提醒或项目末尾；有效经验才进 DEVLOG，不把旧 TODO 整批或汇总倒入。
5. 结果与必要检查、说明同步满足后才完成本包；里程碑另核对阶段总体条件及必要人工确认，不能以任务全勾选代替。
6. 在不变的授权内继续下一项。正常修正、文档同步和工具选择不逐包请批；用户明确停止则立即停下。

## 图示、验证与交付

新建或获准整体重整 DESIGN 时至少一张对应实际项目的 UML 结构图，普通小改不自动补绘或重整；其他 UML 视图按真实关系需要补充。架构图包括组件、系统环境和部署，指定 Figma：可编辑节点、文字、连线配套导出 PNG/SVG 和原图入口；不可用时标明未完成，不用 Mermaid 冒充。其他位置是否配图及边界/布局由真实关系决定，不强制容器、方向或层数。其他流程、时序、状态或计划图按语义用 Mermaid、PlantUML 或既有工具。

审阅最终 diff，检查未跟踪新文件、相关链接与 git diff --check；已有暂存内容另查 git diff --cached --check。验证与风险相称，工具缺失不自动安装。解析、构建、加载、模拟、实际使用和长期观察分开报告，未检查层保持未验证；源码证据不替代安装、运行或消费者证据。

正文整理不等于文件删除许可；固定引用、用户材料和恢复点保留。回收另核对精确对象、使用者及可恢复方式，不永久删除或清空回收站。

仅在新实质授权、目标/关键边界变化、唯一权威不明、证据否定当前安排或无法安全恢复时请求决定。汇报结论在前，说明实际结果、可点击入口、验证、限制和下一步；不播报命令、虚构百分比或堆过程报告。
