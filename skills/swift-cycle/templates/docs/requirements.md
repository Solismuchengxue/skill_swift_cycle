# 项目名称 需求说明

状态：草案。更新日期：YYYY-MM-DD。保留已确认且仍有效的需求；愿景在蓝图、办法在设计、行动在计划。

## 目标与场景

写谁在什么情境遇到什么问题，希望得到什么结果；简写依据并链接愿景或已确认来源。

## 范围与非目标

写确认能力、行为边界、不承担事项及必要取舍。确认不等于立即安排实施。

## 需求与验收

逐项写具体行为、可观察通过条件与重要失败行为；跨文档引用时再加稳定编号。

教学例：R1 列出清单缺项，齐全显示“无缺失”；R2 读取失败明确报错，不返回“无缺失”。此例不是本项目实现或验证，生成正文时替换为确认事实。

## 约束与质量

只写适用环境、兼容、性能、安全或数据要求及判断方法，不虚构阈值。多角色/状态难讲清才配图，界面行为难讲清才配原型。

## 待确认事项

写未定问题、影响与确认办法；没有写“暂无”。收到新需求先核对验收和当前工作影响，确认后进入有效需求，选入当前工作才调整设计与安排。已完成阶段后的新需求安排后续包，不无故推翻原完成判断。
