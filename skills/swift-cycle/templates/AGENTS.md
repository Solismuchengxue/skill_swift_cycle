# 项目名称 项目执行规则

只写项目差异与真实执行要求，不复制全局规则或历史批准过程。

## 适用范围与权威

写作用范围、事实来源与已采用流程，链接需求、设计和用户说明；明确有关 Skill 的读取条件。

## 环境与执行入口

引用已有环境依据，写执行位置和项目真实命令；不另维护重复的运行时版本清单或安装教程。

## 工作与同步规则

写项目差异、同步触发与记录策略。每包同步相关说明、整理重复及引用，不等项目结束。持续采用 Swift Cycle 须有用户授权；已有绑定可在此合并。

定位根级 TODO.md、DEVLOG.md，说明读取与记录策略。获准创建/正式初始化依 Swift Cycle 文档职责核对并补齐；只读/普通维护/仅采用不自动初始化，不在本文件复制完整流程。

执行 Swift Cycle 的可写任务前必须建立/复用根级 tmp/，Git 默认忽略 /tmp/，已有内容与跟踪冲突不自动改动。可控临时文件集中于此，工具目录参数或子进程设置优先，尽量减少额外 C 盘写入；只读任务只检查，不创建或改 ignore。不能控制的位置说明原因，不改用户/系统级临时环境或全局缓存，具体冲突和回收边界依 Skill 临时目录约定。

## 授权与停止边界

写可自主推进的范围及真实副作用的停止条件。技能采用不授权安装、删除、发布、部署、凭据或消费者切换；正常修正和同步不逐包请批。

## 验证要求

按改动对应检查入口及结论边界，内容/链接、行为用例、运行验收分别判断；未验证不写成通过。

获准初始化完成前读回双文件有效内容及适用的跟踪/忽略状态；缺失、无效或冲突明确未完成，非 Git 检查不适用。结构变化按既有设计定位与相关回归验证，不以栏目齐全代替行为证据。

采用/初始化完成时同时核对根级 tmp/ 和适用的 Git 忽略；普通可写任务先核对该临时目录，不把仅存在系统临时目录当作达标。
