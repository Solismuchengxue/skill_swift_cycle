# 项目名称

用一句话说明给谁解决什么问题，给明显的开始入口；影响使用的状态与限制放在前面。

## 用途与适用范围

写使用者、用途、适用环境及关键边界；能力用短句，区分已提供和设想。

## 准备条件

只写实际需要的环境、账户和材料；涉及凭据与权限时在本节补充，秘密不进入说明、聊天或命令参数。

## 安装或接入

给推荐入口、执行位置、Shell、步骤、替换值和成功判断。首装与已有安装分别讲清；有多端选择时在本节说明。

## 第一次使用

提供可复制的最小任务和预期结果，让新用户可以判断成功。图形界面用真实净化截图，命令行用实际菜单或输入输出，库/Skill 用调用示例；未实现示例明确标记。

## 日常使用与求助

给常用操作、常见失败及真实求助入口；有接口参考、开发与贡献需要时在本节链接，不复制详细正文。

涉及配置、更新或撤销安装时，在下节前按顺序增补“配置与数据”“更新与迁移”“暂停、恢复与卸载”，仅保留适用项。横幅、徽章和动图按需采用，状态真实，不依赖任意 CSS 或 JavaScript。

## 限制与许可

写已知限制、未验证范围和实际许可来源；未知不能写成“不适用”，不擅自授予许可。
